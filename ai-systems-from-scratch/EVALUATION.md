# Evaluation Discipline & Rigor Guide

> **Core Foundational Rule:**
> **No Evaluation = No Claim of Improvement.**  
> *"It feels better," "The demo looked nice,"* and *"The loss went down"* are completely disqualified as engineering evidence. Every system change must be justified by reproducible deterministic, semantic, or slice evaluations.

---

## 1. The Pre-Optimization Questionnaire

Before modifying a prompt, fine-tuning an adapter, compiling a model, or changing an agent loop, you MUST complete and document these seven answers:

```text
1. WHAT CAPABILITY SHOULD IMPROVE?
   (Be specific: e.g., "Correct JSON schema output on nested customer orders",
    "Time-to-first-token under 30ms for 256-token prompt")

2. WHICH EVALUATION MEASURES IT?
   (Name the dataset, rubric, exact-match test, or benchmark script)

3. WHICH CAPABILITIES MIGHT REGRESS?
   (e.g., General knowledge QA, formatting compliance, safety boundaries)

4. WHAT BASELINE EXISTS?
   (State baseline metric: e.g., "Current pass rate: 64.2% on 200 held-out cases")

5. HOW LARGE IS THE EVALUATION SET?
   (Minimum 100+ cases for statistical signal; power analysis required)

6. WHICH SLICES MATTER?
   (e.g., Short prompts vs >2k token prompts; edge cases; syntax errors; latency p95/p99)

7. WHAT DEFINES SUCCESS?
   (e.g., "Pass rate >= 85% with zero regressions on safety slice and TTFT <= 40ms")
```

## 3. Combating LLM-as-Judge Biases

When using a model to evaluate another model, you must explicitly counter known biases:

1. **Position Bias:** An LLM judge often prefers candidate A over candidate B simply because it appeared first.
   - *Mitigation:* Always run evaluations twice: `(A, B)` and `(B, A)`. If the judge flips preference based on position, mark the trial as an uninformative tie.
2. **Verbosity Bias:** Models disproportionately reward longer, verbose answers regardless of correctness.
   - *Mitigation:* Normalize score for length; instruct the judge explicitly: *"Penalize extraneous fluff; reward concise, direct correctness."*
3. **Self-Enhancement Bias:** A model family (e.g., GPT, Claude, LLaMA) tends to give higher marks to outputs generated by its own family.
   - *Mitigation:* Blind the judge to model identity and use multi-model consensus or independent human calibration sets.

## 4. Statistical Rigor: Confidence Intervals

Never claim an improvement based on a 2% change on 50 samples.
For binomial proportion evaluations (pass/fail rate $p$ on $n$ samples), calculate the 95% Wald or Wilson score confidence interval:
$$\text{CI}_{95\%} \approx p \pm 1.96 \sqrt{\frac{p(1-p)}{n}}$$

| Sample Size ($n$) | Measured Pass Rate ($p$) | 95% Margin of Error ($\pm$) |
| :--- | :--- | :--- |
| **30** | 70.0% | $\pm 16.4\%$ (Essentially meaningless) |
| **100** | 70.0% | $\pm 8.98\%$ |
| **500** | 70.0% | $\pm 4.01\%$ |
| **1000** | 70.0% | $\pm 2.84\%$ |

If your baseline is $70\%$ and your new run is $74\%$ on only 100 samples, the confidence intervals overlap completely. **Do not claim an improvement without sufficient statistical power.**
