# The First-Principles Service Map

This matrix operationalizes the core teaching principle:
```text
Problem ──► Underlying Need ──► Simplest Solution ──► Limitations ──► AWS Primitive ──► When NOT to Use
```

| Problem | Underlying Need | Simplest Solution | Limitations of Simple Solution | AWS Primitive / Service | Tradeoffs / When NOT to Use |
|:---|:---|:---|:---|:---|:---|
| **Users remember domain names, not IP addresses** | Authoritative Domain Name Resolution | Host BIND DNS on a single VM | Single point of failure; lacks Geo/latency-based routing; DDoS target | **Amazon Route 53** | Don't use if your DNS is already managed at Cloudflare/registrar and you don't need AWS-native alias records. |
| **Global users experience high latency downloading static files** | Edge Caching & Anycast Routing | Increase web server bandwidth; host files directly on web server | Long transatlantic round-trips (150ms+); expensive server egress bandwidth | **Amazon CloudFront** | Don't use for strictly internal private intranet apps with no external internet users. |
| **Single web server crashes under traffic; cannot scale beyond 1 box** | Layer 7 Reverse Proxy & Load Balancing | Round-Robin DNS across multiple server IPs | DNS caches IP addresses; dead servers still receive traffic for TTL duration | **Application Load Balancer (ALB)** | Don't use for raw TCP/UDP gaming or financial protocols where microseconds matter (use NLB instead). |
| **Need general-purpose compute with full OS control and custom packages** | Virtualized Compute Instance | Buy physical 1U rack server | Weeks of procurement lead time; idle capacity waste; manual hardware repair | **Amazon EC2** | Don't use if your workload fits into ephemeral stateless containers or event-driven functions (ECS / Lambda). |
| **Microservices need packaging, isolation, and fast deployment** | Container Scheduling & Orchestration | Run Docker engine on a single EC2 instance | No automated rescheduling if EC2 crashes; manual port management | **Amazon ECS (Fargate)** | Don't use if you have an existing multi-cloud Kubernetes deployment and require exact upstream K8s APIs (use EKS). |
| **Code runs rarely or in response to events; paying for 24/7 VM is wasteful** | Ephemeral Event-Driven Compute | Cron job on a small VM waking up every 10 minutes | Idle VM costs 24/7; concurrency limit bounded by VM CPU/RAM | **AWS Lambda** | Don't use for long-running continuous processes (>15 min), heavy GPU training, or ultra-low sub-millisecond latency. |
| **Need to store millions of user uploads, logs, and backups durably** | Distributed Object Storage | Attach a large 10TB hard drive or EBS volume to server | Limited to single machine; disk corruption risks; cannot scale to petabytes | **Amazon S3** | Don't use as a high-IOPS transactional boot disk or POSIX filesystem requiring byte-range file locks (use EBS/EFS). |
| **Application requires structured relational schemas, ACID transactions, and SQL** | Managed Relational Database | Install PostgreSQL on an EC2 instance | You must manage backups, OS security patches, replication failover, and disk resizing | **Amazon RDS** | Don't use for unstructured key-value access at massive horizontal scale (use DynamoDB). |
| **High-frequency key-value lookups (100k+ QPS) with predictable single-digit ms latency** | Distributed Partitioned Key-Value Store | Sharded Redis or Cassandra cluster | Operational burden of partition rebalancing, compaction, and quorum tuning | **Amazon DynamoDB** | Don't use if you need complex relational multi-table JOINs, ad-hoc OLAP analytics, or flexible schema queries. |
| **Relational database overloaded by repetitive read queries** | In-Memory Key-Value Caching | Cache query results in local server process memory | In-memory cache is lost when server restarts; cache is not shared across servers | **Amazon ElastiCache (Redis/Valkey)** | Don't add Redis preemptively without measuring database read bottlenecks first! Adds cache invalidation complexity. |
| **Service A produces work faster than Service B can process it** | Durable Asynchronous Message Buffer | In-memory Python `queue.Queue` | Lost completely on process crash; cannot distribute work across multiple worker machines | **Amazon SQS** | Don't use if you require strict pub/sub broadcast to multiple independent subscriber systems (use SNS/EventBridge). |
| **Single business event (e.g. OrderPlaced) must notify multiple independent systems** | Publish/Subscribe Broadcast Fan-Out | Service A makes synchronous HTTP calls to Services B, C, D | Cascading failure if D is down; slow response to client; tight coupling | **Amazon SNS** | Don't use if you need message persistence, buffering, or delayed consumer processing (pair SNS with SQS queues). |
| **Need declarative event routing, schema filtering, and SaaS integrations** | Enterprise Event Bus | Custom routing microservice parsing JSON payloads | Must maintain routing code, handle retries, dead-letters, and schema drift | **Amazon EventBridge** | Don't use for ultra-high throughput streaming data (millions of records/sec; use Kinesis instead). |
| **Cannot see application performance, crashes, or capacity exhaustion** | Centralized Telemetry & Alarming | SSH into instances and run `tail -f /var/log/syslog` | Unscalable across 100 instances; logs lost when instances terminate; no alerting | **Amazon CloudWatch** | Don't use CloudWatch for long-term cold analytics without lifecycle rules—storage costs add up rapidly. |
| **Need fine-grained identity, access control, and temporary credentials** | Cryptographic Authorization Engine | Hardcoded API keys in application configuration | Compromised keys provide unlimited access; impossible to audit who did what | **AWS IAM & STS** | Don't create static IAM users and long-lived access keys when IAM Roles and SSO sessions can be used. |
| **Need an isolated private network in the cloud with custom IP routing** | Software-Defined Virtual Network | Host-based iptables firewalls on public IPs | Every server exposed to raw public internet; complex per-host firewall rules | **Amazon VPC** | Don't use complex multi-VPC transit gateways for tiny single-purpose web apps. |
