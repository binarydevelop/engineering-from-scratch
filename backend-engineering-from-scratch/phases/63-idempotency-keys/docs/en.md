> **Motto**: Idempotency keys prevent duplicate operations by allowing clients to safely retry requests after network timeouts.

## Motto
"Idempotency keys prevent duplicate operations by allowing clients to safely retry requests after network timeouts."

## Problem
A client submits a payment, the server charges the card and commits, but the network drops before the response returns.

## Prediction
The client retries; without an idempotency key, the server charges the customer a second time.

## Why this matters
With an idempotency key, the server recognizes the duplicate key and returns the cached previous result immediately.

## First principles
Idempotency Key: Unique UUID generated by client representing the intent of a specific mutation.

## Mental model
```text
Client POST /payments (Key: abc) -> Processed & Stored -> Network Drops -> Client retries (Key: abc) -> Return Cached Result
```
