# Operating Systems Mental Models: From Silicon to Userspace

> **Core Philosophy:** An operating system is not magic; it is an orchestrated collection of state tables, hardware protection boundaries, and asynchronous event handlers. When you visualize the state transitions, bugs become obvious.

---

## 1. The Five Essential Boundaries

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        USER SPACE (Ring 3)                             │
│   Python / Java / Go Runtimes ──► Application Code ──► libc / glibc    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ System Call (syscall instruction)
┌───────────────────────────────────▼────────────────────────────────────┐
│                       KERNEL SPACE (Ring 0)                            │
│  Syscall Dispatcher ──► VFS / Sockets / Scheduler / Virtual Memory     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Driver Command / Memory Bus
┌───────────────────────────────────▼────────────────────────────────────┐
│                       PHYSICAL HARDWARE                                │
│          CPU Cores ──► MMU / TLB ──► RAM ──► NVMe / NIC                │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Mental Model: The Anatomy of a System Call

When your code calls `write(fd, buf, count)`:
1. **Userspace Setup:** The C runtime library places the syscall number (e.g. `1` for `sys_write` on x86_64) into the `rax` register and arguments into `rdi`, `rsi`, `rdx`.
2. **CPU Mode Switch:** The processor executes the `syscall` assembly instruction.
3. **Privilege Transition:** The CPU transitions from User Mode (Ring 3) to Supervisor/Kernel Mode (Ring 0), switches to the process's kernel stack, and jumps to the kernel's system call entry table.
4. **Kernel Execution:** The kernel verifies memory pointers, checks permissions, retrieves the file descriptor from the process table, and invokes the underlying driver or filesystem.
5. **Return to Userspace:** The kernel places the return value into `rax` and executes `sysret` / `iret`, dropping privilege back to Ring 3.

## 3. Mental Model: File Descriptors, Open File Objects, and Inodes

Why do two processes writing to the same file sometimes share an offset and sometimes overwrite each other?

```text
Process A (PID 100)                     Process B (PID 200)
┌──────────────────────┐                ┌──────────────────────┐
│ FD Table             │                │ FD Table             │
│ FD 0 -> stdin        │                │ FD 0 -> stdin        │
│ FD 1 -> stdout       │                │ FD 1 -> stdout       │
│ FD 3 ──┐             │                │ FD 3 ───────┐        │
└────────┼─────────────┘                └─────────────┼────────┘
         │                                            │
         ▼                                            ▼
┌──────────────────────────────────┐   ┌──────────────────────────────────┐
│ Kernel Open-File Description 1   │   │ Kernel Open-File Description 2   │
│ - Current Offset: 1024           │   │ - Current Offset: 0              │
│ - Flags: O_RDWR                  │   │ - Flags: O_RDONLY                │
│ - Reference Count: 1             │   │ - Reference Count: 1             │
└────────────────┬─────────────────┘   └────────────────┬─────────────────┘
                 │                                      │
                 └──────────────────┬───────────────────┘
                                    ▼
                 ┌──────────────────────────────────────┐
                 │ Active VFS Inode (In-Memory)         │
                 │ - Inode Number: 524109               │
                 │ - File Size: 40960 bytes             │
                 │ - Permissions: 0644                  │
                 │ - Disk Block Pointers                │
                 └──────────────────────────────────────┘
```

* **File Descriptor (Per-Process):** An integer handle private to the process.
* **Open File Description (System-Wide Kernel Object):** Tracks cursor position (offset) and access mode. `fork()` copies the FD table, meaning parent and child point to the *same* Open File Description and share file offsets!
* **Inode (Filesystem Object):** Represents the actual file metadata and storage blocks on disk.

## 4. Mental Model: Virtual Memory & Address Translation

A process never sees physical RAM. Every memory address generated by a CPU instruction is a **Virtual Address**.

```text
32-bit or 48-bit Virtual Address
┌───────────────────────────┬───────────────────────────┐
│     Virtual Page Number   │       Byte Offset         │
└─────────────┬─────────────┘─────────────┬─────────────┘
              │                           │
              ▼                           │
        ┌───────────┐                     │
        │ TLB Cache │ (Hit: instant)      │
        └─────┬─────┘                     │
              │ (Miss: walk Page Table)   │
              ▼                           │
        ┌───────────┐                     │
        │Page Table │                     │
        └─────┬─────┘                     │
              │                           │
              ▼ Physical Frame Number     │
┌───────────────────────────┬─────────────▼─────────────┐
│   Physical Frame Address  │       Byte Offset         │
└───────────────────────────┴───────────────────────────┘
Physical RAM Address on Memory Bus
```

* **Page Fault:** If the Virtual Page Number has no valid entry in the Page Table (or the page is stored in swap space on disk), the MMU raises a hardware exception (`Page Fault`), pausing the thread while the kernel fetches the bytes into a RAM frame.

## 5. Mental Model: The Network Socket Lifecycle

A common bug is confusing a **Listening Socket** with a **Connected Socket**:

```text
                 Server Process
                       │ socket()
                       ▼
                 [Unbound Socket]
                       │ bind(8080)
                       ▼
                 [Bound Socket]
                       │ listen(backlog=128)
                       ▼
               [Listening Socket] ◄────── TCP SYN arrives
                       │                 3-Way Handshake completes
                       │                 Connection placed in accept queue
                       │ accept()
                       ▼
             [Connected Socket] (New FD!)
             - Local:  0.0.0.0:8080
             - Remote: 192.168.1.50:54210
             - Reads / Writes payload
```

* The **Listening Socket** only accepts handshakes; it never transmits data.
* The **Connected Socket** represents the established 4-tuple `(SrcIP, SrcPort, DstIP, DstPort)`.

## 6. Mental Model: What Is a Container?

Containers are not lightweight virtual machines. There is no hypervisor, no guest BIOS, and no guest kernel.
A container is simply **a regular host Linux process** wearing five isolation jackets provided by the Linux kernel:

```text
      ┌────────────────────────────────────────────────────────────┐
      │                      CONTAINER PROCESS                     │
      │                                                            │
      │ 1. Namespaces (Isolation: PID, Network, Mount, UTS, IPC)   │
      │ 2. Cgroups (Resource Accounting & Quotas: CPU, Memory, IO) │
      │ 3. Chroot / Pivot_root (Root Filesystem View)              │
      │ 4. Capabilities (Decomposed Root Privileges)               │
      │ 5. Seccomp (Syscall Whitelisting)                          │
      └─────────────────────────────┬──────────────────────────────┘
                                    │
                       Shared Linux Host Kernel
                                    │
                                 Hardware
```
