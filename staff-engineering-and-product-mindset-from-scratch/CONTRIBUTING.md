# Contributing to staff-engineering-and-product-mindset-from-scratch

Thank you for contributing to this curriculum! Our goal is to provide the most rigorous, realistic, and practical training ground for staff-level engineering leadership and product mindset.

---

## 1. Core Principles for Contributions

1. **Grounded in Realistic Scenarios**:
   * No vague platitudes ("be a great communicator", "influence people").
   * Every lesson, case study, or drill must begin with an ambiguous, messy technical/organizational scenario with competing incentives and incomplete information.
2. **Mandatory Artifact Production**:
   * Contributions must require the learner to produce tangible engineering leadership artifacts: RFCs, ADRs, Project Briefs, Postmortems, Stakeholder Maps, or Executive Summaries.
3. **Template Adherence**:
   * All lessons must strictly follow [`LESSON_TEMPLATE.md`](LESSON_TEMPLATE.md).
   * All case studies must follow [`CASE_STUDY_TEMPLATE.md`](CASE_STUDY_TEMPLATE.md).
   * All decision drills must follow [`DECISION_TEMPLATE.md`](DECISION_TEMPLATE.md).
4. **Product Mindset Mandatory**:
   * Every technical intervention must explicitly connect to user problems, business outcomes, and measurable metrics.
5. **Blameless & Systems-Oriented**:
   * Incident leadership and organizational dynamics must focus on systemic conditions, feedback loops, and cognitive load rather than individual fault.

---

## 2. Pull Request Guidelines

1. Fork the repository and create your feature branch:
   ```bash
   git checkout -b feature/phase-xx-refinement
   ```
2. Ensure all markdown adheres to clean GitHub Flavored Markdown standards.
3. Verify that the case study or scenario includes an expert evaluation rubric with trade-off analysis.
4. Submit your pull request with a clear description of the concept taught, the scenario introduced, and the artifacts produced.
